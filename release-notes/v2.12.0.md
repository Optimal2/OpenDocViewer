## Changes Since v2.11.0

### OCR: searchable text and read-aloud (off by default)

- **Self-hosted OCR behind one switch.** `ocr.enabled: true` turns on text recognition of scanned pages in the browser with a self-hosted Tesseract engine (the engine, worker and Swedish and English language files ship in the viewer's `ocr/` folder and load lazily; nothing is sent to an external service). It is off by default, and only the literal value `true` turns it on. Recognition starts with the displayed page and its neighbours, uses a bounded queue and cache, removes the ruling lines of tables and forms from a copy of the page image before recognition (`ocr.removeRulingLines`, on), and can cover the whole document in the background (`ocr.recognizeWholeDocument`, off). PDF pages that already carry a text layer are searched without OCR.
- **Selectable text layer and search.** Recognised text is shown as a selectable layer over the page, laid out so the browser's own find matches phrases, with word-accurate selection painting. The toolbar search finds text in the recognised pages, counts its reach, lists hits in original page numbers, can be limited to the displayed page, supports Escape and announces results through a live region; `ocr.search.overridesCtrlF: true` lets Ctrl+F open it (off by default). `ocr.search.enabled: false` keeps only a status indicator.
- **Read-aloud with local voices only.** A selection or the page can be read aloud from the page's context menu, with the reading language chosen under the language menu or guessed per page among the OCR languages ("Auto"). Only voices installed on the computer are offered; an online voice is never used. `ocr.speech.enabled: false` removes it.
- **Content-Security-Policy.** The shipped HTML meta and IIS policies now allow `'wasm-unsafe-eval'` in `script-src`, which OCR and pdf.js WebAssembly decoders need. It does not allow JavaScript `eval` or `new Function` and adds no script origin. Sites that serve the viewer through their own policy (such as ODVGateway) must add `'wasm-unsafe-eval'` only where OCR is enabled.

### PDF signatures

- **The viewer checks signatures on its own.** Signature inspection uses only the document bytes the viewer already holds and makes no network request; it behaves the same with and without ODVGateway. The trust request to ODVGateway introduced in v2.11.0 is gone, so older gateways no longer answer a signature request with 404.
- **Signing times and RFC 3161 timestamps are verified**, and document timestamps are checked separately from the signatures they protect.
- **Warnings only for real problems.** What the viewer cannot check itself is shown as "Not checked in the viewer" with an information line instead of a warning; `pdfSignatures.uncheckedSeverity: 'warning'` restores the warning colour. Defects stay errors. An unknown ECDSA curve is no longer guessed from the key length (it caused a false red verdict), an oversized ECDSA integer is reported as malformed, and an unreadable source no longer falls back to "no signatures".
- **Hardened revision analysis.** Hidden or out-of-range linearization dictionaries, shadowed signed objects and structural streams that fill signed references are treated as changes after signing; linearized files and DSS-only appends that do not change signed content are accepted. The verdicts are cross-checked against pdf.js in a differential test suite.

### Manual

- **Standard manual filtered by the site's features.** `help.manual.source: 'standard'` shows the bundled manual and hides the sections of features the site has switched off (fine tuning, the overlay and curtain views, PDF signatures, OCR search and read-aloud). `'auto'` (default) still prefers a site manual in `help/site/`, and an auto manual that falls back to the bundled one is filtered the same way.
- **Stand-alone manual page at `<ODV base>/manual/`.** The manual can be opened in its own browser tab, with the viewer's theme and language menus and the same contents tree, search and image viewer as the dialog; the dialog links to it. The page loads the site configuration from the viewer's base, follows `help.manual.enabled: false` (which also hides the Manual entry), and ships its own IIS security headers and no-cache rule in the bundled `web.config`.
- **Keyboard and focus.** The manual dialog keeps focus inside the dialog in the document order, honours disabled controls and leaves native media controls reachable; responsive image URLs are rewritten for the dialog.

### Viewer

- **Key tips.** Holding `?` shows the name of every visible toolbar button under it; releasing the key hides them again.
- **Context menu from the keyboard.** The page's context menu opens from the keyboard and can be navigated with it.
- **Toolbar menus scroll** instead of running off the window on small screens, and a page drawn before a rotation is kept when the canvas size is re-applied.
- **Portable Document Bundle from the browser.** `?sessionurl=` and `?bundleUrl=` also accept same-origin `blob:` URLs, so a host page can build the bundle in the browser. They go through the same fetch path as http(s), with the same 180-second timeout and 256 MB size cap.

### Dependencies, security and packaging

- **Advisories.** follow-redirects moves to 1.16.3 (CVE-2026-116689, in axios's Node.js adapter, which the viewer bundle does not use) and the development-only override for minimatch moves to `^11.0.4` (CVE-2026-118764, eslint toolchain only). `npm audit` reports no advisories.
- **Dependency baseline.** pdfjs-dist 6.5.438 (pinned exactly; annotation and signature rendering still locked by Vitest and Chromium regression tests), tesseract.js 7.0.0 (new), pkijs 4.0.1, @peculiar/x509 3.1.0, i18next 27.0.1 with react-i18next 18.0.0 (the viewer sets `returnEmptyString: true` so intentionally empty strings stay empty), jsdom 31.0.0, and the eslint, jsdoc and Express toolchains on their latest majors. Every package that was behind by a patch or minor release moves to the latest on its line, and the transitive `overrides` floors are raised accordingly.
- **Release artifacts.** Default checkout line endings are pinned so the dist archive and OMP artifact are reproducible. Each release still carries the CycloneDX SBOM next to the dist archive.
- **OMP packaging (internal).** The OMP component `opendocviewer-web` is versioned in `omp-components.json` alongside the release; the runtime-config SRI is also injected into `manual/index.html`, and the portable PowerShell tests run in CI. Agent documentation regenerated.

## Upgrade Guidance

Upgrade v2.11.0 deployments to v2.12.0. No site-configuration change is required: OCR is off by default and the new keys keep the v2.11.0 behaviour when they are absent. If the IIS site uses its own `web.config`, copy the `manual/index.html` location block (security headers and no-cache) from the bundled one, and add `'wasm-unsafe-eval'` to `script-src` only if OCR is enabled; a reverse proxy or gateway in front of the viewer needs the same CSP change for OCR. Sites that want users to read only about the features they have switched on set `help.manual.source: 'standard'`; a site manual in `help/site/` is then not used. Signature checking no longer contacts ODVGateway, so the gateway's `signatures` settings no longer affect the viewer. Build and Node.js requirements are unchanged from v2.11.0.
