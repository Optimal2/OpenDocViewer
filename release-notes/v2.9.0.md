## Changes Since v2.8.0

- **A real user manual ships with the viewer.** `public/help/default/` now contains a complete, customer-neutral manual in English and Swedish: a getting-started guide with the selection and more-features guides embedded, the two guides on their own, a PDF of each, and screenshots. The help menu still tries `help/site/manual.<lng>.html` first, so an installation's own manual keeps precedence and is never overwritten by an upgrade; the sample files in `help/site/` are never used as a manual.
- **The help menu no longer shows the application instead of the manual.** Hosts with an SPA fallback (the IIS rewrite in `web.config`, `vite preview`) answered a missing site manual with `index.html` and status 200, which hid the bundled manual on every installation without a site manual. The candidate logic (`src/utils/manualSources.js`) now skips an application-shell response, and `public/web.config` excludes `help/` from the fallback so missing help files answer 404.
- **Printing no longer hangs when the page's Content-Security-Policy blocks the print frame.** When the hosting CSP lacks `blob:` in `frame-src`, the hidden print frame turns cross-origin and the readiness probe threw outside the error handling, leaving "Preparing print 100 %" open with a cancel button that did nothing. The probe is now handled: a cross-origin frame falls back to the window path, and a blocked fallback reports an error. Covered by a test of the load-event print path.
- **Thumbnails.** The compact thumbnail-only view no longer fails when the navigation modifier state is absent.
- **Log servers.** The optional system-log and user-log servers key their rate limiters through `ipKeyGenerator`, so IPv6 clients are grouped by subnet; express-rate-limit 8 rejected the previous raw-IP key at startup.
- **Dependencies.** jsdom 30.1.1, dotenv 18.0.4, Babel 8.0.6 (runtime 8.0.5), DOMPurify 3.4.16, file-type 22.1.1, react-i18next 17.0.15, morgan 1.12.1, ESLint 10.11, Vite 8.3.1, rolldown 1.2.11, Vitest 5.0.2, Prettier 3.9.9, and raised override floors for path-to-regexp (8.4.2) and picomatch (4.0.7). `npm audit` reports no advisories.
- **Node.js.** The supported engines are `^22.22.2 || >=24.15.0`; CI builds on Node 22.23.3.
- **Documentation and tooling.** README remade with verified architecture, flows and screenshots; runtime-configuration, architecture and deployment docs describe the manual order; private companion repositories are referred to generically; the local CI gate runs the shared-script check (Check 15) strictly; agent documentation regenerated.

## Upgrade Guidance

Upgrade v2.8.0 deployments to v2.9.0. Build hosts need Node.js 22.22.2 or later on the 22 line (24.15.0 or later on 24). Installations without a site manual will show the bundled manual from the help menu after the upgrade; installations with `help/site/manual.<lng>.html` keep showing their own. If the IIS site uses its own `web.config`, add the same `help/` exclusion from the SPA rewrite so a missing help file answers 404. No site-configuration changes are required.
