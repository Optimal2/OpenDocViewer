## Changes Since v2.7.0

- Allowed `blob:` in the Content-Security-Policy `connect-src` directive so documents opened from a blob URL load instead of being blocked by the policy shipped in v2.7.0. The change is applied consistently in `index.html` and `public/web.config`, and the deployment documentation now states which sources the directive has to permit.
- Resolved all six open Dependabot advisories and continued the routine patch/minor dependency upkeep, keeping the v2.7 dependency baseline current.
- Documented and test-covered the configuration coercion contract in `documentLoadingConfig`: integer-only settings such as worker counts, page thresholds, and batch sizes floor their value, while the float sibling keeps its fraction. Picking the wrong one was previously silent.
- Added a guard that fails the OMP package build when an artifact payload contains runtime configuration files, with its own test script, so site configuration cannot be shipped inside an artifact by accident.
- Removed test paths that could not fail and corrected one that asserted nothing, so the suite reports what it actually verifies.
- Documented `npm test` in the README and the review checklist, and refreshed the committed agent documentation packet so CI validation sees the mapping files as current.

## Upgrade Guidance

Upgrade v2.7.0 deployments to v2.7.1. The blob-URL fix matters for any deployment that opens documents from generated object URLs; those failed to load under the v2.7.0 policy. No configuration changes are required.
