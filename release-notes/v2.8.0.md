## Changes Since v2.7.1

- **PDF pages render at print quality by default.** The lazy page pipeline used to rasterize every PDF page at a fixed factor of 2.0 relative to PDF points, which looked soft on ordinary screens and printed poorly. The new `documentLoading.render.pdfResolution` policy defaults to `mode: 'auto'` with `targetDpi: 300`: an A4 page becomes 2480 × 3509 pixels, the same on a small laptop screen, a large monitor and on paper. `fullPageScale` remains a backwards-compatible alias and a floor, so a site that set 4.0 never gets less than 4.0; `mode: 'fixed'` keeps the previous fixed policy. Safety caps bound the raster on every path (40 megapixels per page, halved on the low runtime memory tier, plus the browser render-surface limits), so very large pages are lowered instead of failing.
- **The one-shot resolution boost works again, and honestly.** It doubles the effective factor past the policy ceiling within the safety caps, keeps the current page visible until the sharper raster is committed instead of racing an ordinary render that used to win silently, and keeps the on-screen size in the free zoom mode. A page that already sits at the caps is marked as such: the button is disabled with its own tooltip rather than pretending a boost was applied.
- **Site configuration failures are visible.** When `odv.site.config.js` is found but not loaded (wrong MIME type, integrity mismatch, script error) the viewer logs a console warning and exposes `window.__ODV_SITE_CONFIG_STATUS__`; the support diagnostics include that status together with the effective PDF resolution policy and the latest factor.
- **Custom-size zoom menu.** Only the window-width limit is shown by default; window height and actual size sit behind a discreet "Advanced" link that starts collapsed every time the menu opens.
- **Dependencies.** Resolved the four open Dependabot advisories (browserslist, qs, @humanfs/node, fflate), moved the test runner to Vitest 5, and updated the baseline: React 19.3, Vite 8.3, rolldown 1.2.8, pdf.js 6.3.289, express-rate-limit 8.7, morgan 1.12, @vitejs/plugin-react 6.1.1. `npm audit` reports no advisories.
- **OMP packaging.** The module seed SQL no longer registers artifacts or seeds artifact pointers; those rows are platform-owned and the seed keeps existing pointers instead. The component-version validator is canonicalized under `scripts/omp` with lockstep, payload-tooling and shared-script drift checks, and the pre-push hook runs the local CI gate.
- **Documentation.** New runtime-configuration and deployment sections on PDF resolution, the boost, and why a site override may not apply; agent documentation regenerated.

## Upgrade Guidance

Upgrade v2.7.1 deployments to v2.8.0. Expect PDF pages to rasterize larger than before (roughly four times the pixels of the old 2.0 factor), which costs more render time on first view and more local cache space; the memory caps keep individual pages bounded. To keep the previous behaviour, set `documentLoading.render.pdfResolution.mode` to `'fixed'` in the site configuration. Deployments whose site configuration did not seem to apply should read `window.__ODV_SITE_CONFIG_STATUS__` in the browser console after upgrading; it names the reason.
