## Changes Since v2.10.0

PDF signatures become visible in the viewer, each installation can choose its default theme, the toolbar and compare view get operator-requested refinements, the manual opens in near full width, and the OMP theme is shared with the host.

### PDF signatures

- **PDF signatures are read and shown.** Signed PDF files get a signature symbol next to the document label ("DOK n") in the thumbnail strip, a discreet symbol on every page thumbnail of a signed file, and one signature overview button in the toolbar listing every signed document. The dialog shows signer, signing time (local time), reason, integrity (intact, modified after signing, digest mismatch, invalid, unreadable) and — when ODVGateway v0.1.44 with `signatures.enabled` answers — the server's trust verdict with a plain-language explanation for each of the gateway's reason codes; without a gateway the trust line says the trust has not been checked and why. Multi-file documents show one tab per file. The browser-side parser (pdf-lib, pkijs, asn1js) verifies the signed digest and the signature over the ByteRange bytes in a worker; a signature that cannot be parsed is reported as unreadable, never as an error that breaks rendering.
- **Security of the signature path.** Signatures are discovered independently of PDF headers (prefixed files included), the integrity rules were hardened against bypasses found in review (bytes appended outside the signed range never pass, certification signatures with appended bytes stay invalid), the inspection queue is bounded, worker recovery is limited, gateway trust is restricted to the viewer's origin and gateway source-pack documents are validated.
- **Loading time is never affected.** Inspection starts only after the first page is shown, runs in a worker on bytes the viewer already holds, one PDF at a time; unsigned PDFs pay no measurable cost. Junk-prefix and comment-run probing are linear for every line-ending style, so large files stay fast. Two runtime-config keys keep it out of the way entirely: `pdfSignatures.enabled: false` turns inspection off (no worker bytes, no gateway request, no symbols) and `pdfSignatures.inspectAfter: 'allPages'` defers it until the whole loading run is ready (it also starts after an aborted loading run). `pdfSignatures.thumbnailPageBadge: false` hides only the per-page symbol.
- **Accessible overview.** The signature overview has no interactive controls nested in list options, and the background is inert while its dialogs are open.

### Viewer

- **Default theme per installation.** `theme.defaultMode` (`"system"` default, `"light"`, `"dark"` or `"normal"`) in the site configuration decides the theme while the browser has no stored choice. A stored choice — including an explicit System — still wins; the setting only sets the first impression on a fresh browser profile.
- **Theme.** The viewer shares the OMP light/dark choice with the host through a validated iframe bridge, keeps the Normal palette, and preserves focus visibility, print surfaces and selection contrast across themes.
- **Toolbar.** A "Larger toolbar buttons" checkbox in the theme menu (default on, stored like the other preferences; `toolbar.largeButtons: false` makes compact the site default), 2 px air between group frames and their buttons without changing the toolbar height, equal-width 1:1 / 1:X zoom buttons, English strings replaced by Swedish ones where the UI language is Swedish.
- **Compare view.** The zoom controls sit in a hover-expanding zone behind the pane's selection ring instead of overlapping the page.
- **Visual fixes.** Disabled buttons in the print-selection view use a light solid border in the theme's border colour instead of a thick dashed one; the sticky document header measures its height again after the thumbnail option gained a frame; the manual overlay is readable in the dark theme (its text colours follow the viewer theme, tips and warnings are tinted instead of fixed light boxes); the manual search field shows one clear button instead of two.

### Manual and localization

- **Manual.** The help dialog uses near full width with a sticky contents tree on the left built from the manual's headings; lightbox fragments, authored id reservation and focus return were fixed. The bundled manuals no longer carry a "New in version" section (the manuals describe the product, release notes describe changes); PDFs regenerated.
- **Localization files carry a content hash and are served with `no-cache`**, so a new release never shows stale strings.

### Dependencies and packaging

- **pdfjs-dist 6.4.299**, with annotation and signature rendering (visible and invisible signature appearances, widget annotations) locked by Vitest and Playwright fixtures so the next renderer bump cannot move them silently. Other dependencies are on the nightly patch/minor baseline (including dotenv 18.0.5); `npm audit` reports no advisories.
- **OMP packaging (internal).** The OMP component `opendocviewer-web` is versioned in `omp-components.json` alongside the release and was bumped for OpenModulePlatform's deterministic artifact packer (byte-stable artifact packages); the component-version validator helpers were synced from OpenModulePlatform. Agent documentation regenerated.

## Upgrade Guidance

Upgrade v2.10.0 deployments to v2.11.0. No site-configuration change is required: signature inspection is on, does not touch loading time, and shows "trust not checked" unless the deployment also runs ODVGateway v0.1.44 with `signatures.enabled: true`. Sites that want no signature reading at all set `pdfSignatures.enabled: false` in the runtime configuration; sites that want a fixed first theme set `theme.defaultMode`. Build and Node.js requirements are unchanged from v2.9.0.
