# ODV Proxy App (IIS)

Minimal IIS application that only reverse-proxies ODV log endpoints:

- `POST ./log` → System Log server (e.g., `http://localhost:3001/log`)
- `POST ./userlog/record` → User Log server (e.g., `http://localhost:3002/userlog/record`)

## Requirements

- IIS URL Rewrite module
- IIS Application Request Routing (ARR) with proxying enabled
- `HTTP_X_FORWARDED_HOST` in `allowedServerVariables` for this application

The user-log server compares the browser's Origin/Referer host with the public host, and ARR replaces `Host` with the upstream address, so the user-log rule forwards the public host in `X-Forwarded-Host`. The setup script allows that server variable for this application's location only. ARR's server-wide `preserveHostHeader` is not changed.

What the setup script changes for the whole server:

- Always, when a proxy rule is enabled: it turns ARR proxying on (`system.webServer/proxy`, `enabled`).
- Only with `-ForwardClientHeaders`: it unlocks the configuration section `system.webServer/rewrite/allowedServerVariables` (`appcmd unlock config`), which lets every site and application on the server define that section in its own `web.config`.

Everything else is scoped to this application.

Things to know:

- **Run the setup script again after an upgrade.** The user-log rule has to forward `X-Forwarded-Host`. With a `web.config` generated by an earlier version the user log server answers browser posts with `403`, unless ARR's `preserveHostHeader` is on.
- **The user-log upstream (`-UserLogUrl`) must be a loopback address** (`localhost`, `127.0.0.1` or `[::1]`). The user log server trusts `X-Forwarded-Host` from loopback only; the script warns about any other address.
- **The `allowedServerVariables` entry stays.** It is written for this application's location in `applicationHost.config`. The script has no uninstall, so the entry remains after the application is removed until an administrator deletes it.
- With `-ForwardClientHeaders` both rules also set `X-Forwarded-For` and `X-Forwarded-Proto`, and the system-log rule sets `X-Forwarded-Host`.

## Deploy

Use the repository-root script `scripts/Setup-IIS-ODVProxy.ps1` (run from the repository root, not from this folder) to:
- Create the IIS application (default path `/ODVProxy`)
- Generate `web.config` from `web.config.template`
- Toggle each proxy rule on/off
- Point rules to your target backend URLs

## Test

From the repository root, run `scripts/Test-ODV-IISProxy.ps1 -BaseUrl https://your-host/ODVProxy/`. It posts one
system-log and one user-log request and exits 0 when both return HTTP 2xx, otherwise 1.
